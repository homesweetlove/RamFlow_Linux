# 설계 메모

## 윈도우판과 어떻게 대응되나

| 윈도우판 | 리눅스판 | 비고 |
|---|---|---|
| 압박 점수(EMA, 히스테리시스, 연속 확인) | 같은 방식 (`policy.rs`) | 입력이 PSI·사용 가능 메모리·스왑·CPU로 바뀜 |
| 메모리 우선순위 / CPU 우선순위 낮추기 | `setpriority` (nice 값) | **스레드마다** 따로라서 모든 스레드에 적용 |
| Working Set 줄이기 | `process_madvise(MADV_PAGEOUT)` | 선택 기능, 기본 꺼짐 |
| 원래 값 저널, PID 신원 확인 | 같은 방식 (`journal.rs`) | 신원 = PID + 시작 시각 + 부팅 ID |
| 앞에 있는 창 보호 | X11 `_NET_ACTIVE_WINDOW` (`xprop`) | Wayland는 불가 |
| 분리된 엔진 + 이름 있는 파이프 | 단일 프로세스 + 명령줄 | 화면을 만들 때 유닉스 소켓으로 분리 예정 |
| 트레이/화면 | 없음 | 아직 |

## 구조

```
main.rs      명령줄 (status / doctor / run / restore)
engine.rs    판단 엔진. 한 번의 tick = 측정 → 압박 판정 → 양보/원복/정리
policy.rs    점수 계산, EMA, 히스테리시스
provider.rs  운영체제와 맞닿는 유일한 경계 (Provider 트레이트)
proc.rs      /proc 읽기와 해석 (순수 함수 + 가짜 /proc 로 시험 가능)
journal.rs   되돌리기 기록 (원자적 쓰기)
foreground.rs 앞 창 알아내기 (xprop, 제한 시간 있음)
config.rs    설정 해석
sys.rs       libc 호출 몇 개 (외부 라이브러리 없이 직접 연결)
```

엔진은 `Provider`만 알기 때문에, 시험에서는 가짜 운영체제를 끼워서 "압박이 오고 가는" 상황을 마음대로 만들 수 있습니다. 진짜 시스템 시험은 같은 엔진에 진짜 `LinuxProvider`를 끼우고 압박 수치만 강제로 정합니다.

## 왜 이렇게 했나

- **적어준 것만 건드린다.** 앞 창을 알 수 없는 환경(Wayland)에서도 안전해야 해서, "건드려도 되는 것"을 사용자가 허락하는 방식이 기본입니다.
- **기록 먼저, 변경은 나중.** 순서가 반대면 그 사이에 죽었을 때 되돌릴 방법이 없습니다.
- **스레드 전부.** `setpriority(PID)`는 대표 스레드 하나만 바꿉니다. 여러 스레드 작업이 실제로 양보하려면 전부 바꿔야 합니다.
- **한가하면 아무것도 읽지 않는다.** 한가할 때는 작은 파일 3개(`meminfo`, `stat`, `pressure/memory`)만 읽고, 프로세스 목록은 바쁠 때나 되돌릴 게 남았을 때만 훑습니다.
- **외부 라이브러리 없음.** 필요한 libc 함수가 몇 개뿐이라 직접 연결했습니다. 파일이 작아지고 점검할 것도 없습니다.

## 압박 점수

메모리 압박 = 다음의 가중 평균 (없는 센서는 빼고 나머지로 계산)

| 입력 | 0점 | 100점 | 가중치 |
|---|---|---|---|
| 사용 가능 메모리 비율 | 25% 이상 | 5% 이하 | 0.40 |
| PSI some (10초 평균) | 0% | 25% | 0.35 |
| PSI full (10초 평균) | 0% | 10% | 0.15 |
| 스왑 사용률 | 20% 이하 | 100% | 0.10 |

CPU는 사용률을 그대로 씁니다. 두 값 모두 EMA(0.4)로 부드럽게 만든 뒤, 들어가는 기준과 나가는 기준을 따로 두고(히스테리시스), `confirm`번 연속으로 넘어야 상태가 바뀝니다.

## 앞으로 할 일 (제안)

1. 엔진과 화면을 유닉스 소켓으로 분리하고 트레이 화면 만들기
2. 압박 때의 앞 창 응답 지연을 실제로 재는 시험 (윈도우판의 측정 방식을 따라)
3. arm64와 여러 배포판에서 시험
4. cgroup 기반 양보(`cpu.weight`, `memory.high`)를 선택 기능으로 추가
